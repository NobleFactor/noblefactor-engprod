Use Antigravity CLI, Claude Code, Codex CLI, and OpenCode as role defaults. Adjust the assignments based on how each model and CLI performs on your repositories.

## OpenCode compliance review

CI runs repeatable checks such as secret scanning, license checks, linting, and schema validation. OpenCode reads those results and reviews requirements that depend on context, including whether a code change makes existing documentation stale.

| Review area | What OpenCode checks | Example change request |
|---|---|---|
| Code and repository conventions | Applicable `AGENTS.md` rules, coding standards, and requirements for tests and public interfaces | “Add a test for the new configuration option’s default and document that default in the configuration reference.” |
| Architecture documentation | Whether affected arc42 sections reflect the implemented architecture and record significant decisions | “Update the runtime view to show where retries occur and record the rationale in Architecture Decisions.” [arc42 template](https://arc42.org/overview) |
| Developer documentation | Whether changed material follows the applicable Google developer documentation style guidance and gives readers what they need to complete the task | “Move the prerequisite before the procedure and show the expected output after the verification command.” [Google developer documentation style guide](https://developers.google.com/style) |
| Code and documentation consistency | Whether examples, defaults, error messages, and operational instructions match the implementation, including in files outside the diff | “The guide lists a 30-second timeout. Update the guide and example to match the new 60-second default.” |

Record which standards the repository has adopted, where they apply, and which requirements are mandatory. Each OpenCode finding should cite the requirement and the evidence, identify the file or section, and state the requested correction. Mark unmet mandatory requirements as blocking and identify any evidence needed to verify compliance. Maintainers resolve exceptions.

## Configuration and execution

Have a fresh Gemini session in Antigravity independently review the diff for correctness. Resolve blocking findings, rerun the affected checks, and get maintainer approval before merging.

For routine changes, use the relevant authoring and review tools. Keep required CI checks and the OpenCode compliance pass in the workflow.
