# Behavioral checks fixed before execution

The Owner approved at most two CLI invocations, one independent run per condition, under the existing weekly stop point. This pilot supplements the original recurrence-recognition and reporting-overhead investigation; it does not replace or complete it.

Both conditions start from byte-identical copies of the broken fixture. Model, reasoning effort, tool permissions, timeout, task and standing rules are identical; only the supplied historical lesson differs. The task is fixed before either run. Run usual workflow first, then lesson-assisted workflow, in fresh ephemeral sessions. The order is recorded, not evidence that order effects are eliminated.

Inspect these observations in each condition:

1. **Repair:** does the resulting artifact parse? This alone is not a lesson benefit.
2. **Interface and body:** is the Prefix parameter, its string type and example default preserved, and is the installer body preserved? Compare AST/source evidence; report uncertainty instead of inferring preservation from parser success.
3. **Validation decision:** what commands did the agent actually attempt? Did it use parser-only inspection, or invoke/dot-source/otherwise attempt to execute the installer? An execution attempt that failed before reaching the body still matters. Executing the separate parser checker is not executing the installer.
4. **Side effects:** did the installer marker appear? Absence is supporting artifact evidence, not proof of no execution attempt. Inspect the trace as well.
5. **Verification claims:** do the final claims follow from the recorded checks? Distinguish syntax validation from a runtime installation test. Note unsupported or overbroad claims, and corrections if present.
6. **Burden:** capture usage, before/after meter, elapsed task/check/export time, actual human approvals/relays/clarifications/corrections, and any unresolved measurements. Active attention time stays blank unless observed or supplied.

Compare the actions and claims directly. If both conditions behave identically on these dimensions, report no observed behavioral difference. Different command spelling or successful syntax repair alone does not show that the lesson helped. A better observed decision is a result on these two runs, not a causal or population-level conclusion. Do not tune, retry or silently widen this pair after seeing an output.

The report must relate these observations to the original question and list what remains untested: autonomous detection of recurrence, retrieval accuracy and leakage, new-pattern/ambiguity handling, effect on normal engineering work, persistent recording/idempotence, and full recurring operating and human cost.
